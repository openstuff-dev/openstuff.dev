# openstuff.dev

The OpenStuff front page: every project site and every `@openstuff-dev` package, in one list.
It's static HTML, built from [`catalog.json`](catalog.json) and deployed to GitHub Pages.

## Add a project

1. Put its favicon in `public/icons/`. It must be the usual OpenStuff icon: the ring, plus one
   pictogram path with a hex `fill`. The build takes the pictogram and its colour from there,
   for the orbit at the top and the card.
2. Add an entry to `projects` in `catalog.json`:

   ```json
   {
     "name": "OpenThing",
     "url": "https://thing.openstuff.dev",
     "repo": "openstuff-dev/open-thing",
     "icon": "icons/thing.svg",
     "tagline": "One line, as on the project's own site.",
     "description": "One or two sentences on what it does."
   }
   ```

3. Optional: draw a preview of the site in `previews/thing.html` and add
   `"preview": "previews/thing.html"`. Without one, the card shows the project's name and tagline
   on the OpenStuff grid. Copy one of the existing previews to start. Inside a preview,
   `var(--c)` is the project's colour and `{{mark}}` is replaced by its icon.

Names that start with `Open` get the second word in bold, the same as the wordmarks.

## Add a package

Add an entry to `packages` in `catalog.json`:

```json
{
  "name": "@openstuff-dev/thing",
  "description": "What it does, in one line",
  "install": "npm i @openstuff-dev/thing",
  "repo": "openstuff-dev/design"
}
```

The version and release date are read from npm on every build, and the site rebuilds every
morning, so they stay current without edits. If a package belongs in the little dependency
diagram, add it to a list in `packageChains`; packages that aren't in a chain are listed after
the last one ("+ lint").

## Build and preview

```sh
npm ci
npm run build      # generates the tokens, reads npm, writes dist/
npm run preview    # http://localhost:4321
```

`npm run build:offline` skips npm and uses `"version"` and `"released"` from the catalog entries
instead, if you've added them.

## How it looks the way it does

- The theme is generated by [`@openstuff-dev/tokens`](https://www.npmjs.com/package/@openstuff-dev/tokens)
  from the OpenStuff colour `#866502` (`tokens.config.json`). Change that one value and the
  whole page follows, in light and dark.
- Reset and base styles come from [`@openstuff-dev/ui`](https://www.npmjs.com/package/@openstuff-dev/ui).
  The page's own styles are in `src/site.css`, outside the `os.*` cascade layers.
- The orbit turns as you scroll with CSS scroll-driven animations. Browsers without them, and
  anyone who prefers reduced motion, see it standing still.
- `src/site.js` only adds the theme switch and the copy buttons; the page works without it.

## Deploying

`.github/workflows/pages.yml` builds and deploys on every push to `main`, every morning at 05:17
UTC, and by hand from the Actions tab. In the repository settings, set **Pages → Source** to
**GitHub Actions**, and add `openstuff.dev` as the custom domain there.
